# توال العالمية — V13

تطوير مبني على ملف V11 المرفق، لإدارة صيانة مكيفات المدارس. واجهة عربية بسيطة للمدرسة، وقائد الفريق، والمدير. هذه نسخة مصدرية غير منشورة.

## التشغيل مع Codex أو محلياً

يتطلب Node.js 22 أو 24 وnpm. استخدم نسخة المستودع الحالية؛ لا حاجة لإنشاء worktree.

```bash
npm ci
cp .env.example .env.local
npm run dev
```

املأ إعدادات `.env.local` محلياً أو عبر أسرار بيئة الاستضافة. لا تضع القيم في GitHub أو المحادثات. لا يحتاج بناء المشروع إلى مفاتيح حقيقية؛ استقبال البلاغات وتسجيل الدخول يحتاجانها.

- `/`: نموذج المدارس (الولاية، المدرسة، الهاتف، ثم بيانات المكيفات).
- `/login`: دخول الموظفين بحسابات ينشئها مسؤول النظام فقط.
- `/dashboard`: متابعة المدير أو بلاغات قائد الفريق حسب صلاحيات الحساب.
- `/reports/[id]`: تقرير محمي بجلسة الموظف؛ بيانات التواصل مخفية افتراضياً، مع طباعة PDF من المتصفح.

## إعداد Supabase وTurnstile

1. نفذ ملفات `supabase/001` إلى `008` بالترتيب في مشروع Supabase تجريبي أولاً. الملفات ليست معدة لإعادة تطبيقها كلها على قاعدة موجودة؛ طبق فقط الترحيلات غير المنفذة، مع نسخة احتياطية.
2. في ملف `005_admin_review.sql`، نفذ جملة إضافة قيمة ENUM وحدها وانتظر اكتمالها، ثم نفذ بقية الملف في معاملة أخرى.
3. أنشئ حسابات المدير وقادة الفرق عبر Supabase Auth. أضف UUID لكل حساب إلى `staff_profiles` مع `display_name` ودور `admin` أو `leader` و`active=true`. لا توجد كلمات مرور افتراضية.
4. ضع عنوان Supabase والمفتاح العام في متغيري `NEXT_PUBLIC_SUPABASE_*`. مفتاح الخدمة `SUPABASE_SERVICE_ROLE_KEY` للخادم فقط.
5. أنشئ Turnstile لنطاق التطبيق. ضع مفتاح الموقع العام والمفتاح السري واسم المضيف في المتغيرات الموضحة في `.env.example`. اسم المضيف دون بروتوكول أو مسار. التحقق يفرض تطابق المضيف و`action=school_ticket`، ويمنع الإرسال عند نقص الإعدادات.
6. يحتاج المتصفح والخادم الوصول إلى `challenges.cloudflare.com`، ويحتاج التطبيق الوصول إلى نطاق مشروع Supabase الخاص بك. أضف النطاق الفعلي لإعدادات الشبكة عند الربط.

## التحقق

```bash
npm run check:source
npm test
npm run build
npm run typecheck
npm start -- --hostname 127.0.0.1 --port 3000
```

في طرفية ثانية بعد بدء الخدمة شغّل `npm run smoke` لاختبار الصفحات ورفض الطلبات غير الصالحة. تشغيل الخدمة محلي داخل بيئة العمل وليس نشراً. راجع `VALIDATION.md` للنتائج والحدود. عند تغيير المتغيرات العامة يجب إعادة البناء لأنها تدمج في ملفات المتصفح وقت البناء.

## تحسينات V13

- إصلاح ترتيب `use client` وتعريف قطع الغيار في التقرير لإتاحة البناء، وإضافة القائد ومدد الزيارات بالتقرير.
- نموذج المدرسة بخطوتين واضحتين، وعدّاد المكيفات، وتمييز الحقول الاختيارية، دون تغيير دليل المدارس أو حد 10 مكيفات.
- Turnstile فعلي بدلاً من إدخال الرمز يدوياً، مع معالجة انتهاء الصلاحية وإعادة التحقق بعد الإرسال.
- بطاقات بلاغات لقائد الفريق على الجوال، ووحدات صيانة قابلة للطي، وقسم قطع غيار مطوي، والتحقق من الكميات وتنبيه النتائج غير المحفوظة.
- ملخص حالات للمدير، تصفية بالحالة والقائد وبحث وتحديث يدوي، وإخفاء الإسناد في الحالات التي ترفضها قاعدة البيانات.
- عرض سبب إعادة التقرير لقائد الفريق عبر ترحيل `008` وسياسة RLS مقيدة ببلاغه.
- عميل جلسة واحد وتجديد رمز المصادقة عند العمليات، وزر تسجيل خروج، ورسالة نجاح الحفظ.
- استجابة 400 للـJSON غير الصالح، ومهلة اتصال للتحقق الأمني، وعدم طباعة تفاصيل أخطاء قاعدة البيانات.
- تحديث Zod إلى الإصدار المصحح وتجاوز PostCSS إلى إصدار 8 مصحح مع الإبقاء على Next.js 15، ثم تثبيت الاعتماديات عبر `package-lock.json`، واختبارات وفحص CI وتعليمات Codex.

## قبل الاستخدام الفعلي

لم تختبر هذه النسخة على Supabase أو Turnstile حقيقيين دون توفير إعداداتهما. اختبر دورة كاملة: إرسال بلاغ، إسناده، بدء زيارة، حفظ النتائج والمتابعة، إنهاء الزيارة، إعادة المدير مع السبب، ثم الاعتماد. اختبر حسابي قائد فريق للتأكد من عزل البلاغات ومحاولات الوصول المباشر عبر API وRLS.

قبل النشر يلزم تحديد استضافة وتفعيل حد طلبات موزع عند حافة الشبكة للنموذج العام، واختبار الصلاحيات والنسخ الاحتياطي. لم يضف حد طلبات داخل ذاكرة الخادم لأنه لا يوفر حماية موزعة موثوقة. يمنع زر إنهاء الزيارة مع وجود تعديلات غير محفوظة؛ احفظ كل مكيف قبل الإنهاء. قائمة البلاغات الحالية محدودة بأحدث 200 بلاغ؛ يلزم ترقيم صفحات عند زيادة الحجم.
